## 1. Repository Health Check and Preparation

### Pre-Merge Analysis

```sh
# Create a detailed comparison report
mkdir -p logs
git fetch --all --tags

# Repository status and commit history comparison
# (Example: compare origin/main and upstream/main)
git log upstream/main..origin/main --oneline > logs/commits_diff.txt

# Run automated merge conflict analysis
merge-conflict-detector main feature-branch > logs/merge_conflict_report.txt

# Review the generated report for risk scores, file-specific issues, and recommendations.
```

- Address high-risk files and conflicts as flagged by the tool.
- Document any manual interventions in the merge commit message.

## 2. Merging Workflow

- Always rebase feature branches onto the latest main branch before merging.
- Use progressive squash merges to maintain a linear history.
- Resolve all conflicts as per the recommendations in the merge-conflict-detector report.
- After resolving, re-run the tool to verify no new issues were introduced.
- Ensure all tests and pre-commit checks pass before finalizing the merge.

## 3. Post-Merge Actions

- Push changes to the remote repository.
- Update documentation and prompt files if new patterns or issues were encountered.
- Archive the merge-conflict-detector report for audit and review.
